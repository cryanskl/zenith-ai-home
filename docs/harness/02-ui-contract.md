# UI Contract

## 视觉方向

整体风格：浅色工程杂志。

关键词：

- 清爽
- 专业
- 克制
- 高可读性
- 项目证据优先
- Timeline 作为经历证据链

避免：

- 通用 AI 渐变模板
- 大面积紫蓝赛博背景
- 假 stats
- 营销空话
- 重装饰卡片堆叠
- 纯履历表格

## 页面结构

Hero 必须先回答：

- 这是关于谁的主页
- 关注什么 AI 工程方向
- 当前在探索什么
- 访问者下一步可以看什么

项目模块必须早于 Timeline。原因：面向技术同行时，先展示工程实践，再展示经历证明。

Timeline 不是完整成长日记，而是关键经历证明。每个节点需要回答：

- 发生了什么
- 所在场域是什么
- 是否有遇到的人、名次、奖项或结果
- 为什么它支撑个人品牌

## 布局规则

- 第一屏必须留下下一段内容的可见提示。
- 桌面端主体内容最大宽度控制在可读范围内。
- 移动端 Timeline 不能横向溢出。
- 按钮、卡片、标签内文字不能溢出。
- 不使用负字距。
- 不用 viewport 宽度直接缩放字体。

## 组件规则

- 项目卡片突出 `problem`、`approach`、`stack`、`proof`。
- Prompt 卡片突出 `scenario`、`prompt`、`whyItWorks`、`variables`。
- Reading 卡片突出推荐理由。
- Insight 卡片突出技术判断，而不是普通博客摘要。

## 交互规则

V1 以静态展示为主。

允许：

- 锚点导航
- 外部链接
- hover/focus 状态
- 响应式布局

不允许：

- 假筛选
- 假搜索
- 假订阅表单
- 假数据刷新
- 不可用按钮

## 可访问性

- 使用语义化 section 和 heading 层级。
- 链接必须有可理解的文本。
- 颜色对比必须适合阅读。
- focus 状态不能被移除。
